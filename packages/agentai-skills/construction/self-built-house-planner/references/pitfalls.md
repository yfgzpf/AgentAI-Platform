# 踩坑清单（Pitfalls）

本文件记录自建房规划全流程中**真实踩过**的坑。每条都包含：现象 → 根因 → 解法。
新接手时先读这一页，能省掉大半返工。

---

## 一、几何数据类

### P1　界址点抄错一位数，全案尺寸崩塌
**现象**：反算面积与图纸标注面积差 5% 以上，边长也对不上。
**根因**：界址点坐标表数字密集，人工抄录极易错位。
**解法**：`site_geometry.analyze()` 强制做 `area_check` 与 `edge_check`。
- 面积偏差 ≤1% 才允许继续出图；
- 边长逐条比对，tol 默认 20 mm。
**红线**：面积不闭合时**禁止出图**，先回去核对原始测绘成果。

### P2　把斜界当垂直界放线，退线差出半米
**现象**：东侧退线算出来是 0.45 m，实际放线后只有 0.19 m（或反之）。
**根因**：界址边并非正南北/正东西。实测案例中 J2→J3 边倾角 1.44°，
跨度 12.6 m 时水平偏移达 **0.317 m**。
**解法**：`east_west_slant()` 会逐条给出南北向边的水平偏移与倾角，
**必须写进图纸说明**："按实测坐标放线，不可当垂直线"。

### P3　最大内接矩形算法写成五重嵌套，直接算到超时
**现象**：程序挂住不返回，无任何输出，退出码 1。
**根因**：写成「逐候选宽度 × 逐候选高度 × 三个锚点 × 逐行验证」的嵌套扫描，
10.8 × 12.6 m 地块需约 **7×10¹¹** 次运算。
**解法**：改为**顶点候选法** —— 候选左右边取各顶点 x 值 ± margin，
只枚举 O(nx²) 个宽度，每个宽度沿 y 单次扫描求最长连续段。
同样地块降到约 20 万次运算（毫秒级）。
**注意**：`site_geometry.max_inscribed_rect` 的 docstring 里写了这条禁令，别改回去。

### P4　用户实测尺寸与图纸反算不符
**现象**：业主说"纵深 9.975 m"，测绘图反算是 9.010 m，差 965 mm。
**根因**：两者量的是**不同的东西** —— 业主量的是"主块 + 缺角院子"的总深，
图纸反算的是其中一段。也可能业主量的是含散水或到河岸的距离。
**解法**：不要急着改数。用 `analyze()` 输出各边长 + 外包框，
**逐段与业主对齐"你量的是哪一段"**，同时给出"若按实测重算会变成多少"的对照表。
**唯一正确做法**：以最新权籍成果为准，并在文档中注明"施工前须核定"。

### P5　指北针方向画反
**现象**：图纸指北针指向东南，实际场地朝南偏东 22.85°。
**根因**：混淆"建筑朝向"与"北向在图上的角度"。
**解法**：
- 局部坐标 +X 沿 J1→J2，`meta['bearing_x']` 即 +X 的真实方位角；
- 图纸约定 +X 向右、+Y 向下；
- 指北针旋转角 = `-bearing_x`（用 `draw_lib.bearing_to_screen_rotation()`）。

## 二、绘图渲染类

### P6　SVG 里 font-family 用双引号，整个 XML 坏掉
**现象**：Chrome 渲染报 "Extra content at the end of the document"，页面空白。
**根因**：`style="font-family:"Noto Sans SC""` —— 双引号截断了属性值。
**解法**：**style 属性内一律用单引号**：`font-family:'Noto Sans SC'`。
（自然语言文本不受此限，只有 SVG 属性受限。）

### P7　画布 viewBox 硬编码，改尺寸后图被裁
**现象**：调大房间后图超出画布，或被裁一半。
**根因**：`viewBox="0 0 1010 1210"` 是写死的。
**解法**：viewBox 必须由 `W_` / `H_` 变量拼接。
**特别注意**：不能写 `'...width="100%"...' % (W_, H_)` —— `width="100%"` 里的
`%` 会被当成格式化占位符，直接抛错。**必须用字符串 `+` 拼接**。

### P8　截图窗口尺寸乱写，图形只占画布一角
**现象**：PNG 里图形挤在左上角，右边大片空白。
**根因**：`--window-size=1400,1300` 与 SVG 实际 viewBox 不符。
**解法**：窗口尺寸 **= viewBox 尺寸 × scale**。`shot.py` 已自动读取 viewBox。
另：`html,body{margin:0;padding:0}` 必须设，否则截图多出白边；
零边距之后不需要再做居中裁切。

### P9　房间底色盖住楼梯踏步线
**现象**：楼梯区域看不到踏步线，只有一块底色。
**根因**：**绘制顺序错了** —— `room()` 会填底色，画在 `stair()` 之后就把它盖掉。
**解法**：顺序必须是
`先画同底色矩形 → 画 stair() → 再画 room(fill='none', stroke='none')` 或直接用
`Sheet.stair_l / stair_loop`（内部已处理）。

### P10　长标签溢出遮罩，被线穿过
**现象**："10.85 ㎡ L 型双跑 梯段净宽 1.20" 这类长标签中间被踏步线划断。
**根因**：文字遮罩宽度写死。
**解法**：遮罩宽度按文字长度自适应：
`wm = max(124, len(name)*13.5+20, len(sub)*8.6+20)`，并 `min(wm, 房宽-6)`。
**同时**：图内标注**忌长句** —— 把"梯段净宽 1.20"移到图下方说明里，图面只留房名 + 面积。

### P11　固定构件条的标注压在条上，深底深字看不清
**现象**：神台/玄关柜的标注文字正好落在深色条带内，几乎不可读。
**根因**：标注基线偏移 = 条带高度，文字被条带末尾覆盖。
**解法**：用 `Sheet.fixture_bar()` —— 条带下方留 pad，标注自带浅色遮罩。
**并且**：`fixture_bar()` 必须在 `room()` **之后**调用。

### P12　尺寸线被院子/附属矩形盖住
**现象**：总尺寸标不出来。
**根因**：尺寸线画在主体**下方**，而下方正好是院子、附属房的填充矩形。
**解法**：尺寸线一律放图形外侧，且**优先放上方**；或把院子矩形后画再补尺寸。
三级尺寸分级偏移（细分近、总尺寸远），**不能画在同一条偏移线上**。

## 三、文档生成类

### P13　Word 章首用分页符，多出一整页空白
**现象**：文档里夹着几张全白页。
**根因**：用 `add_page_break()` 插分页符；若上一页恰好排满，就多出一整页。
**解法**：用段落属性 `paragraph_format.page_break_before = True`。
`build_report.Report.h1(text, newpage=True)` 已封装。

### P14　长图插入 Word 溢出版心
**现象**：总平面图（长条形）超出页面下边界，被截断。
**根因**：只设了宽度 `width=Cm(25.5)`，没考虑高度。
**解法**：按纵横比取小值：
```python
r = ih / iw
w = min(max_w_cm, max_h_cm / r)
h = w * r
```
A4 纵向（边距 2.2 cm）可用 16.6 × 25.3 cm。

### P15　表格一行字孤零零落在下一页
**现象**：表格断行，某行只剩一行字在次页顶部。
**根因**：默认允许行内跨页断开。
**解法**：每行 `trPr` 加 `<w:cantSplit/>`；表头行再加 `<w:tblHeader/>` 跨页重复。

### P16　目录页码回读失败（两个连着的坑）
**现象**：`read_page_numbers` 返回空字典，或返回目录页的页码。
**根因（两层）**：
1. PDF 文本提取把「第一章　项目概况」按**全角空格断成两行**，
   整行等值匹配永远失败；
2. 目录页里同样是完整章名清单，且排在正文之前，**先命中目录页**。
**解法**：
1. 整页文本 `''.join(text.split())` 去掉所有空白后再做子串匹配
   （`str.split()` 会吃掉全角空格 U+3000）；
2. **不能写死"跳过 2 页"** —— 目录可能与封面同页、也可能独占数页。
   改为**自动识别目录页**：一页若同时出现 ≥40% 的章名，即判为目录页剔除；
   再优先在页面上部 35% 区域匹配（标题位置）。

### P17　PDF 被阅读器占用，Word 静默失败
**现象**：导出"成功"但 PDF 文件时间没变、内容还是旧版，反复找不到原因。
**根因**：目标 PDF 被阅读器打开时，`SaveAs` 直接写目标会**静默失败**（不抛异常）。
**解法**：**先写临时文件再搬运**：
```python
doc.SaveAs(tmp, 17)   # 17 = wdFormatPDF
os.replace(tmp, dst)  # 占用时抛 OSError，此时另存新名并告知用户
```
`build_report.docx_to_pdf()` 已封装，返回 `(实际路径, 说明)`。

### P18　Word 标题用自定义样式，人工改排版时无从下手
**现象**：业主要自己改局部和排版，发现没有导航窗格、改一处字体全乱。
**根因**：标题是手工设字号的普通段落。
**解法**：用 **Word 内置 `Heading 1` / `Heading 2` 样式**（覆盖字体为黑体、
字号 14 / 11.5、颜色近黑），这样：
- 「视图 → 导航窗格」可逐章跳转；
- 后续可插入自动目录；
- 样式固定，改内容不会把字体带跑。

## 四、流程与协作类

### P19　批量替换脚本 assert 失败 → 前面已成功的替换全部丢失
**现象**：跑了一堆补丁，报错后重跑，发现文件仍是旧的。
**根因**：补丁脚本把「读 → 替换若干处 → 写回」放在一起，
中途 assert 抛异常时**从未执行写入**，前面所有替换白做。
**解法**：
- **分批小脚本**，每批跑完立即验证（grep 目标串 / 看文件时间戳）；
- 或先备份再分段；
- assert 的锚点字符串**要用文件里的实际原文**（含全角空格），
  从终端打印 `repr()` 确认，不要凭记忆写。

### P20　页码递增用顺序 replace，级联出错
**现象**：想把页码 19→20、20→21，结果全变成 21。
**根因**：`replace('19','20')` 之后再 `replace('20','21')`，把刚改出来的也命中了。
**解法**：**整体重写目录块**（重建 `toc([...])` 那段列表），
不要逐条 replace。

### P21　只按业主口述数值改，脱离原始测绘图
**现象**：连续几版尺寸反复摆动，业主越来越不满。
**根因**：每次都照最新一句口述改，没有把**两套数据的差异摊开讲**。
**解法**：遇到尺寸分歧，先输出**对照表**（图纸反算 vs 实测 vs 差额），
说明"差额来自哪一段"，再让业主决策。这次对话里正是靠这张表把话讲清的。

### P22　把"挑空/露台不计面积"当卖点讲
**现象**：业主强烈反感："不要用没有楼板就不计面积的说法"。
**根因**：口径没讲清 —— 规范上挑空、露台确有计入规则，
但业主关心的是**实际能用多少面积**。
**解法**：**两个口径都给**：
- 规范计容口径（报建用）；
- 实际楼板/屋面覆盖口径（业主能感知的"实际建筑面积"）。
并逐层列出面积，不要只说总数。

### P23　未先调研规范就出方案，返工三四轮
**现象**：做出 327 ㎡ 三层半方案，一查省级规定"不得超过三层、300 ㎡以内"，
整版作废。
**根因**：直接按业主"我要 400 平""我要四层"的说法设计。
**解法**：**第一步就做规范调研**（见 `references/compliance-checklist.md`），
把 层数 / 面积 / 覆盖率 / 层高 / 限高 五条硬约束先钉死，
再谈空间布局。业主的口径若与省级不一致，**要书面依据**。

## 五、Word 字体与占位框

### P24　引号字符不在楷体字库里，渲染成空心方块
**现象**：引文块前面出现一个空心小方框。
**根因**：用了 `❝`（U+275D），楷体（SimKai）没有该字形。
**解法**：改用全角书名引号 `「」`（U+300C/U+300D），任何中文字体都有。
**推广**：选特殊符号前先确认目标字库覆盖，尤其是楷体、仿宋这类
覆盖范围窄的中文字体。

### P25　占位框靠空段落撑高，被压成一条线
**现象**：效果图占位框只有一行高，看不出是"待出图"的位置。
**根因**：`add_run('\n')` 在表格单元格里会被 Word 压缩，空段落撑不起高度。
**解法**：用 `<w:trHeight w:val="…" w:hRule="exact"/>` 固定行高
（1 cm = 567 twips），而不是塞空段落。

## 六、接入 AgentAI 平台

### P26　handler.py 不按 `##RESULT##` 协议输出，平台解析不到
**现象**：手工 `python handler.py` 一切正常，但通过 AgentAI 桥接器调用
只返回"缺少 --action 参数"。
**根因**：桥接器（`_lib/_bridge.py`）的约定是——
把 args 翻译成 CLI flag 传给子脚本，并要求子脚本**最后一行**输出
`##RESULT## {json}`。普通 JSON 输出不会被识别。
**解法**：`handler.py` 三件事都要做：
1. 用 `argparse` 收 `--action` / `--input` / `--data` 等参数；
2. 合并环境变量 `AGENTAI_ARGS_JSON`（新式入口）；
3. 最后一行 `print('##RESULT## ' + json.dumps(result, ensure_ascii=False))`。

### P27　桥接器会删掉 args 文件，重复测试必须重新生成
**现象**：第一次跑通了，第二次同样的命令报"缺少 --action 参数"。
**根因**：`_bridge.py` 读完 args 文件后立刻 `os.unlink`，
同一个临时文件不能用第二次。
**解法**：每轮测试都重新写 args 文件。

### P28　60 秒默认超时不够导出 PDF
**现象**：生成 Word 成功，但导 PDF 时被桥接器超时杀掉。
**根因**：`callPython()` 默认 `timeoutMs = 60_000`；Word COM 导出
十几页文档常在 30~60 秒之间，叠加图件渲染就超了。
**解法**：调用时把 `timeoutMs` 提到 180000 以上；
或先用 `build_report` 只出 docx，PDF 单独一次调用导出。

## 七、一句话总纲

> **数据先闭合，规范先钉死，图层从单源出，文档两遍成。**
>
> 顺序错了，后面全是返工。
