# AgentAI Platform：一个会自我进化的开源 Agent 框架，完整工程能力解读

> 写在前面
> 本文基于 AgentAI Platform v0.1.0 源码审计编写，所有数据来自代码仓库实际统计，无夸大。项目技术栈：TypeScript / Node.js 22 / React / Tauri / Python 3.13，全部免费开源。

## 开篇：我们为什么又造了一个 Agent 轮子？

2026 年的 AI Agent 赛道已经拥挤到令人窒息——Claude Code、Cursor、Trae、Windsurf、Devin……每个产品都在宣称"自主编程""全自动执行"。但仔细一看，它们的本质都差不多：**一个 LLM + 一堆工具 + 一个循环**。

真正的差异不在表面功能，而在**工程深度**。

AgentAI Platform 的起点很简单：**如果要用免费模型做到商用模型的水平，需要在框架层做多少补偿？** 这个问题的答案，驱动了我们 2 个月的开发。

核心数据先说清楚：

- **8 个 LLM Provider**（agentai / deepseek / openai / zhipu / superapi / dxnt / sensenova / longcat）
- **141 个工具**（文件操作 / 代码执行 / 搜索 / 浏览器 / 记忆 / 规划 / 媒体生成 / 行业专用）
- **2.5 万行核心代码**（agentai-gateway 约 2.8 万行，agentai-gui 约 1.2 万行）
- **6 步 LLM 修复管道**（从崩溃输出中抢救可用结果）
- **行为规则自进化**（AI 学会后永久记住，不再犯同样的错）
- **4 个垂直行业**（装修建材 / 中医问诊 / 教育 / 法律），行业知识引擎 843 行

## 一、架构总览：三层分离，职责清晰

```
agentai-gui (React + Vite + Antd5)
    │ HTTP / WebSocket
    ▼
agentai-gateway (Node.js 22 · Express · TypeScript)
    │ import
    ▼
agentai-skills (Python 3.13 脚本集)   agentai-core (类型定义)
```

**严格单向依赖**：GUI 只能通过 HTTP/WebSocket 调用 Gateway，不能 import 任何后端代码。Gateway 负责所有核心逻辑，GUI 只是一个"精致的遥控器"。

多端共享同一套 Gateway：Web 前端、Tauri 桌面应用、QQ Bot 渠道，全部通过同一个 API 接口通信。

## 二、主循环：AgentAI Loop，融合了三个框架的精华

`agentai-loop.ts` 是整个引擎的核心（约 5000 行），它融合了三套开源框架的设计哲学，并做了大量自创改进：

**借鉴来源：**
- Reasonix 的 Immutable Prefix / Append-Only Log / Volatile Scratch 三段式架构
- Hermes SessionDB 的 FTS5 全文检索会话存储
- ZhiY.AI 的多智能体编排机制

**自创亮点：**
- **每 10 轮反思门**：写入三层记忆（工作记忆 / 进化记忆 / 项目记忆），防止长任务"失忆"
- **中文 Skills 索引注入**：按意图匹配技能，按需加载，不浪费 token
- **Abort 信号传递**：支持优雅中断，不卡死

### 主循环关键参数

```typescript
MAX_AUTO_RESUME = 10;   // 短回复最多自动恢复 10 次（给慢模型机会）
ABSOLUTE_MAX_MS  = 60 * 60 * 1000;  // 60 分钟绝对超时
IDLE_TIMEOUT_MS  = 10 * 60 * 1000;  // 10 分钟无操作超时
```

循环流程：

```
用户消息
  → buildImmutablePrefix（构建上下文前缀，~8层按需注入）
  → 歧义检测（检测模糊动词/指代/描述/选择）
  → 置信度评估（5维信号，决定是否追问）
  → LLM 调用（通过智能路由选最优模型）
  → 工具调用 / 文本回复
  → 结果写入 log
  → 循环控制（继续 / 总结 / 超时）
  → 60分钟后强制结束（或正常完成）
```

## 三、LLM 智能路由：成本 / 成功率 / 延迟三维评分

`llm-router.ts` 是我们最自豪的模块之一（约 2200 行）。

**核心思路**：不依赖单一模型，而是根据任务特征动态选择最优 Provider。

### 五维评分体系

| 维度 | 权重 | 说明 |
|---|---|---|
| 复杂度匹配 | 30% | 当前任务是简单问答还是复杂推理 |
| 上下文适配 | 15% | 是否有多模态 / 长上下文需求 |
| 成本 | 20% | 免费优先，商用兜底 |
| 成功率 | 25% | 该 Provider 近期历史成功率 |
| 延迟 | 10% | 响应速度偏好 |

### 8 个 Provider 梯队

```
免费层：agentai（自有模型）
    ↓ 失败率 > 30% 时熔断
降级层：deepseek / longcat / sensenova（高性价比商用）
    ↓ 仍失败
保底层：openai / zhipu / superapi / dxnt（稳定商用）
```

### LRU 缓存

相同请求直接命中缓存，不做重复 LLM 调用，大幅节省成本。

### Cost Guard

调用前预检余额，调用后校验实际消耗，双重保障。

---

### 6 步修复管道

这是 AgentAI 区别于其他框架的关键创新。LLM 输出经常不完整或格式错误，我们不直接报错，而是尝试修复：

```
① flatten    — 嵌套对象压平（处理 DeepSeek 推理模型的复杂结构）
② scavenge   — 从 块中抢救 JSON（DeepSeek 推理模型常见）
③ storm      — 检测工具调用风暴（单次返回过多 tool_call）
④ truncation — 补全截断的 JSON（LLM 输出被 cut 时）
⑤ tool call JSON 自动修复 — 尾逗号 / 单引号 / 无引号 key / undefined
⑥ text→tool_call 回退    — 解析 func(args) / ```tool``` / XML / DSML 模式
```

第 5 和第 6 步是**自创亮点**——很多框架在这里直接报错放弃，而 AgentAI 会尝试把自然语言描述"翻译"成工具调用，让弱模型也有机会完成任务。

## 四、模型能力分层：同一套框架，适配不同强度的模型

一个容易被忽视的问题：**免费模型和商用模型的能力差距巨大，但框架不能只针对强模型设计。**

AgentAI 引入了三层能力分级体系（model-classifier.ts），基于 6 维评分自动判定模型等级：

| 等级 | 适用模型 | Prompt 策略 | 引导强度 |
|---|---|---|---|
| **autonomous** | 强模型（Claude/GPT-4 级） | 精简版 ~50 行 | 原则驱动，最小干预 |
| **guided** | 中等模型（免费大窗口，如 Agnes 256K） | 轻度引导 | 核心规则 + 按需提示 |
| **supervised** | 弱模型（免费小模型） | 完整版 ~200 行 | 反摆烂 + 元认知 + PRD 质疑模式 |

这个设计解决了**同一套框架在不同模型上表现一致**的难题。用免费模型时，框架会主动补充"你可能不知道的规则"；用强模型时，框架则克制地少说话，避免喧宾夺主。

此外还有**智能模型切换器**（smart-model-switcher.ts，475 行）：当免费模型触发速率限制时，自动平滑切换到备用 Provider，全程对用户透明，无需手动干预。

## 五、141 工具，但只在需要时发送

工具数量不是越多越好——全量注入 141 个工具定义会吃掉大量 token，弱模型会迷失在噪声中。

AgentAI 的做法是**按意图动态过滤**（tool-filter.ts）：

```typescript
// 根据当前任务类型 + 消息意图，只发送最相关的工具子集
const relevantTools = getRelevantTools(taskType, intent, message);
const toolsFragment = buildToolsFragment(relevantTools);
```

工具分为 7 大类：

| 类别 | 代表工具 |
|---|---|
| 文件操作 | read_file / write_file / multi_edit / undo_edit |
| 代码执行 | run_code / npm_install / ensure_dependency |
| 搜索检索 | web_search / web_fetch / find_references |
| 浏览器 | browser_open / browser_click / browser_type / browser_close |
| 记忆管理 | remember / forget / recall / evolve_prompt |
| 规划决策 | plan_task / update_plan / ask_user / spec_generate |
| 行业工具 | CAD 解析 / 报价生成 / 内容分发 / 销售跟进 |

**自动验证闭环**是文件操作的杀手锏：

```
AI 写文件
  → auto_verify (tsc --noEmit)
  → 有错误 → "⚠️ 编译错误: App.tsx:23 TS2304..." → AI 自动修复
  → 无错误 → 继续
```

**Token 压缩**同样关键（token-compressor.ts）：工具输出超过 1000 字符时自动压缩，噪音过滤 + 重复折叠 + 智能截断，预估节省 70-85% 的工具输出 token 消耗。

## 六、系统指令管理器：解决弱模型被过多指令干扰的问题

2026 年 7 月的一次深度审计发现了一个隐蔽但影响巨大的问题：**多个系统模块同时注入 [SYSTEM] 指令，弱模型会同时收到多条矛盾指令，导致行为混乱。**

比如：歧义检测模块注入"请先追问用户"，同时元认知模块注入"直接执行"，弱模型不知道该听谁的。

`directive-manager.ts`（loop 子模块）的解决方案是**优先级队列 + 延迟缓冲**：

```
[critical] 安全拦截  ← 立即注入，不可推迟
[high]     错误反应  ← 立即注入
[medium]   一般引导  ← 延迟到下一轮，与同类合并
[low]      鼓励提醒  ← 延迟到任务结束再发
```

每轮只取**优先级最高的一条**注入，避免弱模型被信息淹没。同时设计了一套可延迟来源黑名单（meta_ask / boundary_check / low_conf_search 等），这些非紧急指令攒着一起发，而不是打断当前执行。

这是**工程层面解决弱模型表现差**的典型思路：不是去训练更好的模型，而是优化送给模型的输入质量。

## 七、安全：默认全放行，只拦系统路径

沙箱守卫 v3.2 的设计哲学是**"只要不动操作系统权限，全放行"**：

- 默认模式：**allow**（与传统的 deny-first 相反）
- 仅拦截系统路径：`C:/Windows`、`~/.ssh`、`/etc/` 等
- 自动识别盘符（Windows 多盘场景）+ 路径预置面板
- 写文件前自动备份到 `.agentai/backups/`
- API key / token / password 从 LLM 上下文中自动剥离

重复失败检测：同一工具连续失败 3 次 → 强制换方案，不原地打转。

安全模块还包含**self-modify.ts**（自我修改安全审核）：当 AI 调用 `create_tool` 创建自定义工具时，框架自动对脚本进行静态分析，拦截明显的危险模式（如删除系统文件、访问敏感路径），在"全放行"的前提下守住底线。

## 八、自进化：AI 会用越来越久，越用越聪明

这是 AgentAI 最具差异化的能力：

### 8.1 行为规则自修改（evolve_prompt）

```
AI 发现低效模式
  → evolve_prompt({ action: 'add', rule: 'PowerShell不支持&&' })
  → 存入 .agentai/evolved-rules.json
  → 下次对话自动加载注入 system prompt
  → AI 不再犯同样的错
```

### 8.2 工具自创建（create_tool）

```
AI 经常做某操作，但没有现成工具
  → create_tool({ name: 'diff_files', script: '...' })
  → 脚本存入 .agentai/custom-tools/
  → 后续可通过 run_code 调用
```

### 8.3 工作记忆摘要

每 10 轮自动生成结构化摘要（用户目标 + 已用工具 + 进度），注入上下文头部，防止长任务"失忆"。项目记忆超过 30 条自动合并旧条目，保留最近 20 条。

### 8.4 启动感知

首轮对话自动注入：git log（最近 5 次提交）+ 最近改动文件列表，AI 不用从零探索，秒懂项目现状。

### 8.5 记忆蒸馏

`distillation-on-demand.ts` 实现了按需蒸馏机制：当任务完成后，调用强模型将本次执行过程中的经验提炼为可复用的模式，存入蒸馏文件。下次遇到类似任务时，这些经验会作为上下文注入，实现"吃过一次亏，永远不犯"。

## 九、歧义检测 + 置信度评估：让 AI 学会"先问再答"

### 歧义检测（主循环前）

检测 4 类模糊模式：
- **模糊动词**：帮我 / 搞一下 / 处理一下
- **指代不明**：这个 / 那个 / 它
- **模糊描述**：好看的 / 差不多 / 大气一点
- **未决选择**：或者 / 还是 / 要哪种

命中时注入追问提示，引导 AI 调用 `ask_user`，而非瞎猜。

### 元认知决策（MetaCognitiveLoop）

每次 LLM 输出后，评估置信度信号（5 维）：

| 信号 | 说明 |
|---|---|
| 工具覆盖度 | 是否调用了足够的工具 |
| 证据密度 | 输出是否有实质性内容 |
| 不确定性标记 | AI 是否使用了"可能"/"大概"等词 |
| 语义完整性 | 回答是否结构完整 |
| 一致性 | 与上下文是否矛盾 |

决策分支：
- **高置信度 ≥ 85%** → stop，正常结束
- **低置信度 + 需求不明确** → ask_human 追问
- **低置信度 + 知识不足** → web_search 补充

## 十、行业知识引擎：不只是通用 Agent

`industry-engine.ts`（843 行）是一个多行业知识引擎，目前支持 4 个垂直行业：

| 行业 | 核心能力 | 特色工具 |
|---|---|---|
| **装修建材** | 空间报价法、材料用量计算、风格推荐 | 报价生成、材料清单、CAD 图纸解析 |
| **中医问诊** | 十问歌问诊、四诊合参、辨证开方 | 经典检索、医案匹配、处方生成 |
| **教育** | 知识点梳理、学习路径规划、试题生成 | 课程大纲、错题分析 |
| **法律** | 法规索引、合同风险审查、合规建议 | 合同分析、法条引用 |

每个行业的激活过程：
1. 检测文件类型，自动识别所属行业
2. 加载对应知识库（BM25 本地检索）
3. 注入行业专属 system prompt 片段
4. 暴露行业技能给 AI 调用

**知识库采用本地 BM25 检索**（industry-knowledge-base.ts），不依赖外部向量数据库，数据完全本地化，隐私友好。

## 十一、任务快照与断点续传

`task-snapshot.ts`（约 500 行）实现了长任务的中途保存与恢复机制：

- 关键决策点自动快照（任务 ID、会话 ID、上下文摘要、恢复提示）
- 任务中断后重新启动时，自动检测未完成的快照
- 恢复时注入"你之前做了什么、为什么这么做"的上下文，让 AI 无缝接续

这对于 60 分钟超长任务尤其重要——网络闪断、进程重启都不再是灾难。

## 十二、前端：不只是聊天窗口

agentai-gui 基于 React + Vite + Ant Design 5，包含几个精心设计的组件：

- **Thread.tsx**：推理过程可折叠容器（流式展开，完成后折叠）；工具调用合并显示（统计 N成功·M失败）
- **FileCard.tsx**：文件名 + 语言图标 + diff 预览 + 一键下载
- **TaskPlanPanel.tsx**：AI 任务计划实时显示，进度条 + 子任务状态
- **ImageStudio.tsx**：5 模式图像工作室（文生图 / 图生图 / 风格迁移 / 编辑 / 试穿），12 种预设风格
- **ChatView.tsx**：流式对话，throttled localStorage（2 秒写入一次，避免流式阻塞）
- **SessionSidebar.tsx**：对话摘要列表，双击编辑标题

所有颜色均使用 CSS 变量（`var(--bg)` / `var(--fg)` / `var(--panel)` 等），支持主题切换。

## 十四、为什么值得开源？

在 Agent 框架遍地开花的 2026 年，AgentAI 选择了一条不同的路：**不追求最强的单点模型，而追求最完整的工程闭环**。

- ✅ 8 模型智能路由，免费先用，商用兜底
- ✅ 141 工具按需分发，不被 token 预算压垮
- ✅ 6 步修复管道，弱模型也能稳定输出
- ✅ 模型能力分层，同一框架适配所有模型强度
- ✅ 指令冲突管理系统，解决弱模型被多指令干扰的核心痛点
- ✅ 行为规则自进化 + 记忆蒸馏，越用越懂你的习惯
- ✅ 4 个垂直行业 + 本地 BM25 知识库，不是纯玩具
- ✅ 沙箱 v3.2 默认放行，不因安全而阉割生产力
- ✅ 完整的多渠道支持（Web / 桌面 Tauri / QQ Bot）
- ✅ 全部免费，无订阅费，无模型调用限制

这个项目始于 2026 年 6 月，截至 2026 年 8 月，核心代码约 **2.5 万行**，测试覆盖率持续补齐中。

它可能不是最强的单体模型，但它是一个**会思考、会学习、会进化的系统工程**。
